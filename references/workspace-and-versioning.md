# 任务工作区与版本管理规范

本文件描述 skill **未来被用于具体任务**时的文件组织方式。它不是当前 skill 制作任务的执行清单；当前只制作 skill 时，不创建具体任务的 `code/`、跑批目录或脚本副本。

## 工作区结构

每个具体任务使用独立的工作文件夹，推荐结构：

```text
任务工作文件夹/
├─ ai痕迹/
│  ├─ 当次使用的 skill 副本
│  ├─ 分析过程与中间结果
│  ├─ 任务链全局地图的必要快照
│  └─ 其他过程性资料
├─ doc/
│  ├─ 需求资料
│  ├─ 知识库
│  ├─ 任务链说明
│  ├─ 对任务链有用的正式参考文件
│  └─ 任务链名称+组件名称+相对位置（子链资料）
├─ 测试数据/（有测试数据时）
├─ code/
│  ├─ 脚本名称A/
│  │  ├─ backup/
│  │  │  └─ 原始脚本
│  │  ├─ v001/
│  │  │  └─ 原版本（示例）
│  │  └─ v002/
│  │     └─ 当前轮次修改副本
│  └─ 脚本名称B/
│     ├─ backup/
│     └─ v001/
└─ 跑批任务名称/
   ├─ config/
   │  └─ 配置文件
   ├─ result/
   │  └─ 本次跑批结果
   ├─ 启动-命令名称.bat
   └─ code/
      ├─ backup/
      └─ v001/
```

正式 skill 本体可以保留在该工作区的 `ai痕迹/` 外；如果为了记录当次使用版本而复制一份 skill，则副本放进该任务的 `ai痕迹/`。删除 `ai痕迹/` 时，不应误删正式 skill 本体或正式交付资料。

子链对应的 `doc/` 资料文件或文件夹按“任务链名称+组件名称+相对位置”命名；遇到名称不明确或冲突时先询问。用户提供测试数据时，单独保存在工作区根目录的测试数据文件夹中。

## 任务链脚本拆分

如果用户最初提供了任务链文件：

1. 先识别任务链中的后端脚本节点、脚本名称、脚本语言和脚本内容。
2. 每个脚本单独建立 `code/脚本名称/`。
3. 一个脚本一个文件夹，不把多个脚本合并保存，也不使用难以区分的通用文件名覆盖彼此。
4. 拆分完成并建立脚本清单后，再进行需求分析、全局地图建立和修改方案设计。
5. 任务链节点名称、脚本目录名称和实际脚本内容之间建立对应关系；向用户说明时使用组件名称和相对位置，不主动展示节点 ID。

## 修改已有脚本

- 原始脚本只读保存到对应目录的 `backup/`，不直接覆盖。
- 以原版本 `v001/` 为例，本轮修改在复制得到的 `v002/` 持续进行；中途修改、需求调整和阶段审批都不新建版本。
- 用户确认本轮所有需求完成，或主动提出归档后，固定当前版本；下一轮才从固定版本创建 `v003/`。不得主动向用户提示归档命令。
- 如原始版本只有 `backup/` 而无编号，先保留备份，将原件作为 `v001/`，再为本轮创建 `v002/`；不覆盖已固定版本。
- 每个版本目录只放该版本实际使用的脚本及必要说明，避免把不同版本混在一起。
- 如果用户要求备份已确认修改后的脚本，保留对应版本目录，不把后续版本覆盖到它上面。
- 代码修改遵循最小改动；只有架构明显导致维护困难，或有更简单、代码量更少的方案时，才提出架构调整并等待用户审批。

## 跑批脚本

跑批任务与任务链后端脚本分开管理：

- 跑批任务建立独立目录。
- 原始跑批代码先放入 `code/backup/`。
- 根据用户本地电脑创建修改副本，如 `code/v001/`。
- 可变路径、输入文件、输出目录和二次处理参数放在与 `code/` 同级的 `config/` 中。
- 每次跑批结果写入与 `config/` 同级的独立 `result/` 目录，不与配置、代码或备份混放。
- 启动入口与 `code/` 同级，名称写清对应命令；固定命令点击即运行，多个不同命令分别建立入口。仅每次运行需变化的参数才提示用户输入。
- 启动入口不应把用户经常需要修改的路径硬编码在代码深处；启动入口读取配置文件或将配置文件路径作为明确入口参数。
- Windows 路径示例使用用户可以直接复制到终端的形式，例如 `C:\Users\用户名\Documents\input\data.xlsx`。JSON、YAML、批处理文件等格式需要遵循各自的转义规则。
- 需要密钥、Token、账号或密码时先询问用户；没有得到凭据前不伪造配置，也不通过异常兜底绕过鉴权。

## 跑批执行边界

- 默认只制作、检查或修改跑批脚本，由用户自行运行；没有明确授权时不代为执行。
- 用户明确要求“帮我跑一次”时，只授权当前对话中明确指定的这一次，执行完成后授权自动结束。
- 只有用户明确要求后续每次对话都代为运行或表达等价的持续授权时，才可以跨对话继续执行。用户可以随时撤回持续授权；撤回后立即停止代跑，之后须重新获得明确授权。
- 用户自行运行后，读取 `result/` 中的结果继续下一步；结果文件缺失、路径或格式不明时先询问，不擅自猜测。
- 代跑前确认代码版本、配置文件、输入路径和结果目录，避免误跑旧版本或覆盖已有结果。

## 输出与交付

- 大段完整代码写入对应版本目录，回复中提供可点击文件链接和简要修改说明。
- 只有用户明确要求查看代码时，才在对话中展开完整代码；修改代码时文件本身必须是完整可复制版本。
- 需求完成后说明：使用的版本、原始备份位置、确认副本位置、启动入口位置和配置文件位置。
- 真实任务的过程资料放在 `ai痕迹/`，对任务有用的正式资料放在 `doc/`，脚本按独立目录放在 `code/`；不要把一次性业务内容写回通用 skill。
